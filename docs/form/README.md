# Форма в боте: общая логика

Как бот собирает ответы на вопросы — анкета записи на мероприятие (сценарий №1) и
опросник из рассылки админа (сценарий №2). Человеческое описание — `../../ОПИСАНИЕ.md`,
структура данных — раздел «Дополнительные сущности в CRM».

Особенности конкретных мессенджеров: `telegram.md`, `max.md`.

## Решение

Форма собирается **нативными сообщениями и inline-кнопками**: один вопрос — одно
сообщение бота с кнопками (для выбора) или без них (для открытого ответа).
Мини-приложения (Telegram WebApp, MAX mini app) не используем: один бэкенд на два
мессенджера, одинаковое поведение, не нужен хостинг фронта и два разных моста.

## Модель шага

1. Бот отправляет сообщение: «Вопрос 3 из 8», текст вопроса, клавиатура.
2. Ответ приходит к бэкенду одним из двух способов:
   - нажатие кнопки — событие callback от мессенджера;
   - текстовое сообщение участника — для открытого вопроса.
3. Бэкенд записывает «Ответ» в CRM, снимает клавиатуру с сообщения (правкой
   сообщения), переходит к следующему вопросу.

Состояние прохождения хранится в CRM, а не в памяти бота: объект «Прохождение
опроса» (статус, текущий вопрос, канал). Перезапуск и деплой бота не теряют
начатую форму, второй экземпляр бота не ломает прохождение.

## Правила формы

1. Порядок вопросов — по «Порядковый номер», только «Активные».
2. Вопросы с «Спрашивать при каждой записи» (звёздочка) задаются всегда.
   Остальные пропускаются, если у участника уже есть ответ на этот вопрос —
   проверка глобальная, по объекту «Ответ» (в любом опроснике и на любом
   мероприятии).
3. Обязательный вопрос пропустить нельзя — кнопки «Пропустить» в нём нет.
   В необязательном есть «Пропустить».
4. Выбор одного варианта: нажатие сразу считается ответом, кнопки гасятся,
   выбранный вариант остаётся в тексте сообщения.
5. Выбор нескольких вариантов: кнопки работают как переключатели, ответ
   отправляется кнопкой «Готово». Лимит «Максимум выбранных вариантов»
   проверяет бот: в CRM у поля «выбор нескольких» лимита нет. При превышении —
   сообщение «можно выбрать не больше N» и установка лишнего варианта
   отменяется.
6. Открытый ответ: принимается только текстовое сообщение. Команды и нажатия
   кнопок в этот момент игнорируются с подсказкой «ответьте текстом».
7. Идемпотентность: повторное нажатие на уже отвеченный вопрос не создаёт
   второй ответ (кроме вопросов со звёздочкой, где повторный ответ — норма).
8. Сообщение с вопросом редактируется, а не дублируется: одно сообщение — один
   вопрос, история чата не засоряется. Отдельное сообщение отправляется только
   при ошибке или предупреждении.
9. «Отказаться от опроса» — в первом сообщении формы и на каждом шаге:
   прохождение получает статус «отказ», запись на мероприятие не создаётся.
   Отказ пишется в объект «Отказ от опроса» (отказ от всех опросов — отдельной
   кнопкой).
10. Возобновление: прохождение со статусом «начат» живёт до завершения или
    отказа. По команде `/start` бот предлагает продолжить с «Текущего вопроса».
11. Ограничение длины: текст ответа ограничен лимитом мессенджера на сообщение
    (см. файлы мессенджеров). Слишком длинный текст бот не обрезает, а просит
    сократить — иначе потеряется часть ответа.
12. Сеть и лимиты: при ошибке отправки — повтор с задержкой; при ответе
    «слишком часто» — пауза из ответа мессенджера. Дубль сообщения участнику
    недопустим, поэтому каждая отправка логируется (канал, id сообщения, id
    callback).

## Запись на мероприятие

Анкета записи отправляется по кнопке «Записаться» под анонсом мероприятия.
После завершения формы создаётся «Участие в мероприятии» (статус «записан»,
роль участника пустая до выдачи роли), а ответы привязываются к этому
мероприятию. Если прохождение — отказ, запись не создаётся.

## Что не входит в форму

- Роли участника и организатора — выставляются в админке CRM.
- Рассылка анонсов — отдельный сценарий (очередь + подписки на тип мероприятия).
