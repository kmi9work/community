# Форма в Телеграм

Реализация формы (см. `README.md` в этой папке) в Телеграм через Bot API.

## Транспорт

- HTTPS Bot API, токен бота в заголовке/URL метода. Обновления: webhook в
  продакшене, long polling — локально и на тестах.
- Дедупликация по `update_id`: одно обновление обрабатываем один раз, иначе
  повторная доставка создаст двойной ответ.
- Отправка: `sendMessage` (текст + `reply_markup`), правка: `editMessageText`
  и `editMessageReplyMarkup`, ответ на нажатие: `answerCallbackQuery`.

## Ключевые ограничения Bot API

| Что | Лимит |
| --- | --- |
| Текст сообщения | 1–4096 символов (после разбора разметки) |
| Подпись к фото (афиша) | 0–1024 символа |
| `callback_data` в кнопке | 1–64 **байта** |
| Текст всплывающего уведомления (`answerCallbackQuery`) | 0–200 символов |
| Частота | ориентир: ~30 сообщений/сек суммарно, не более ~1 сообщения/сек в один чат |

`callback_data` считается в байтах, а не в символах: кириллица в кнопку не
помещается. В кнопку кладём короткий латинский код, а не JSON и не текст
варианта:

```
q:<номер вопроса>:<номер варианта>          # выбор одного, до 64 байт
m:<номер вопроса>:<номер варианта>:<бит>    # переключатель для выбора нескольких
g:<номер вопроса>                           # «Готово»
s:<номер вопроса>                           # «Пропустить»
x:<номер прохождения>                       # «Отказаться»
```

Расшифровка кода — по данным в CRM (номер вопроса в опроснике), поэтому
переименование варианта не ломает старые кнопки.

## Особенности

1. `answerCallbackQuery` вызывается на каждое нажатие, иначе у участника долго
   крутится «часики», а Telegram повторяет нажатие. Уведомление показываем только
   при ошибке или предупреждении (например, «не больше трёх вариантов»).
2. После ответа правим сообщение, а не шлём новое: `editMessageReplyMarkup`
   с пустой клавиатурой убирает кнопки, `editMessageText` дописывает выбранный
   вариант. Правка сообщения старше 48 часов запрещена — для долгих прохождений
   (вопрос со звёздочкой при повторной записи) вместо правки отправляем новое
   сообщение и гасим старое.
3. Кнопок в одном ряду — не больше трёх: варианты ответов длинные, при большем
   числе Telegram обрезает текст кнопки.
4. Открытый ответ: сообщение бота без клавиатуры, ждём текст. Если участник в
   этот момент нажал кнопку из старого сообщения — обрабатываем как отказ от
   ввода и переспрашиваем.
5. Афиша мероприятия: `sendPhoto` с подписью ≤1024 символа и `inline_keyboard`
   с «Записаться» в том же сообщении; описание длиннее лимита подписи — отдельным
   текстовым сообщением.
6. Рассылка анонсов: очередь и пауза между сообщениями; при ответе API 429 —
   ждать `retry_after`, а не долбить повторами.
7. Диплинк для анонса: `https://t.me/<бот>?start=<payload>` — payload до 64
   байт, только латиница и цифры.
8. Имя и фамилию при регистрации не подставляем из профиля молча: показываем
   «Вас зовут <имя> <фамилия>?» с кнопками «Да» / «Ввести заново».
9. Мини-приложение (WebApp) не используем — решение в `README.md`.

## Источники

Документация Telegram Bot API (core.telegram.org/bots/api), объекты
`InlineKeyboardButton`, `answerCallbackQuery`, метод `sendMessage`. Значения
лимитов сверены по типам из `grammyjs/types`, которые дублируют документацию
(сам core.telegram.org из рабочей сети недоступен).
