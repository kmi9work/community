# Форма в MAX

Реализация формы (см. `README.md` в этой папке) в мессенджере MAX через MAX Bot API.

## Транспорт

- База: `https://platform-api2.max.ru` (не `platform-api.max.ru`).
- **Сертификат платформы.** `platform-api2.max.ru` отдаёт сертификат, выпущенный
  Russian Trusted Sub CA (Минцифры), корневого сертификата которого нет в
  стандартном наборе доверенных. В адаптере (`messengers/max.py`) к `certifi`
  добавляется `russian_trusted_root_ca.crt` из того же каталога; без этого все
  запросы падают на проверке TLS — не регистрируется webhook и не уходят
  сообщения, то есть бот молчит. Корневой сертификат —
  `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`.
- Токен — в заголовке `Authorization: *** передача токена через
  query-параметры больше не поддерживается.
- Обновления: **только Webhook** (`POST /subscriptions`) в продакшене, по HTTPS и
  с сертификатом доверенного центра (в том числе сертификатом Минцифры). С
  25.05.2026 вебхуки по HTTP и самоподписанные сертификаты не поддерживаются.
  Long Polling (`GET /updates`) ограничен по скорости и сроку хранения событий —
  только для разработки: при активной подписке на Webhook он не работает.
- Отправка: `POST /messages` (по `user_id`/`chat_id`), правка:
  `PUT /messages?message_id=...`, ответ на нажатие: `POST /answers?callback_id=...`.

## Ключевые ограничения MAX Bot API

| Что | Лимит |
| --- | --- |
| Текст сообщения | до 4000 символов |
| Вложения в сообщении | до 12 |
| Клавиатура | до 210 кнопок: до 30 рядов, до 7 кнопок в ряду (до 3 — для `link`, `open_app`, `request_contact`, `request_geo_location`) |
| Текст кнопки | 1–128 символов (по вёрстке: 20 — при одной кнопке в ряду, 10 — при двух, 5 — при трёх) |
| `payload` кнопки | до 1024 символов |
| `url` кнопки-ссылки | до 2048 символов |
| Частота | до 2 сообщений/сек и до 2 ответов на callback/сек в один диалог; до 30 rps на бота суммарно |

## Клавиатура и callback

Клавиатура — вложение сообщения:

```json
{
  "text": "Зачем Вы идёте на игру?",
  "attachments": [{
    "type": "inline_keyboard",
    "payload": { "buttons": [[
      { "type": "callback", "text": "Я люблю подобные игры", "payload": "m:3:1:1" },
      { "type": "callback", "text": "Разобраться в тонкостях", "payload": "m:3:1:2" }
    ]]
  }]
}
```

Нажатие приходит событием `message_callback` с объектом `callback`:
`callback_id` (идентификатор нажатой кнопки), `payload` (наш код из кнопки),
`user`. На каждое нажатие нужен `POST /answers?callback_id=...`: ответ может
содержать обновлённое сообщение и/или одноразовое уведомление.

В `payload` помещается до 1024 символов, поэтому, в отличие от Телеграма, туда
можно положить компактный JSON. Всё равно передаём только коды
(`q:<вопрос>:<вариант>`, `m:...`, `g:<вопрос>`, `s:<вопрос>`, `x:<прохождение>`):
так кнопки переживают правку текстов вариантов.

## Особенности

1. Правка сообщения — `PUT /messages?message_id=...`; чтобы убрать клавиатуру,
   передаём пустой массив `attachments` (пустой массив удаляет все вложения).
2. Одновременно с клавиатурой можно отправить медиа: афиша мероприятия — одно
   сообщение `image` + `inline_keyboard`. Клавиатура в сообщении одна.
3. Webhook-endpoint должен отвечать быстро; тяжёлую обработку (запись в CRM,
   следующий шаг) делаем асинхронно, иначе MAX повторит доставку события.
4. Дедупликация: событие несёт `timestamp` и `callback_id` (для нажатий) —
   повторную обработку отсекаем по паре «прохождение + вопрос» в CRM, чтобы
   двойной клик не дал два ответа.
5. Текст ответа на открытый вопрос — обычное сообщение (`message_created`), reply
   на сообщение бота не требуется. Длина — до 4000 символов, как и у исходящих.
6. Кнопки не пересылаются при форварде сообщения в другой чат — если участник
   перешлёт вопрос, кнопок в пересылке не будет; на логику это не влияет.
7. Диплинк: `https://max.ru/<botName>?start=<payload>`, `payload` до 512 символов,
   приходит в событии `bot_started`.
8. Кнопка `request_contact` даёт номер телефона с проверочным `hash`
   (HMAC-SHA256 от `vcf_info` по токену бота). В анкете не используем — имя и
   фамилию вводит сам участник, но для регистрации по телефону это готовый
   механизм.
9. Мини-приложение (`open_app`) не используем — решение в `README.md`.
